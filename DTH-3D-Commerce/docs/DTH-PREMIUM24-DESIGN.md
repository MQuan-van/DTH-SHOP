# DTH Precision — premium interface pass

## Brief and boundaries

Premium motorcycle parts commerce, angular and restrained, using pearl, navy and candy blue.
The real part or motorcycle is the subject. Motion explains selection, inspection and confirmation.
Keep original GLBs/materials, authored Admin presentation, API/auth/cart/checkout contracts,
page-local shortlist semantics, identity guards, native scroll and existing renderer ownership.
Atlas migration remains a separate, unapproved operation; this pass never starts the backend or seeds data.

## Design system

- Pearl #f2f6f7, white #ffffff, navy #102c3d, deep navy #081e2d, blue #287cff, ice #a9d9ef.
- Primary actions use darker blue #155cce with white text; candy blue supplies the edge accent.
- Reuse the installed Manrope stack; no font download or dependency change. Display type is tight,
  body type calm, prices tabular, labels sentence case. No decorative arrows or fake technical claims.
- 4/8px rhythm; 24px mobile and 48–80px desktop gutters. Two-pixel control corners, square stages,
  clear borders and selective depth on primary actions. No rounded-card grid on every page.
- Buttons: 44px minimum target; hover on fine pointers, immediate press feedback, visible keyboard
  focus, native disabled states. Depth uses CSS transforms; no WebGL canvas per button.
- One scoped Studio timeline introduces identity, part title, information and inspection controls;
  it replaces the old DOM entrance hook on the active route. The existing R3F stage entrance and
  camera remain separate owners. Navigation marker animates transform only.
  No extra scroll director, wheel handler, permanent pointer loop or camera animator is added.

## Baseline observations and intended corrections

| Before | After | Why |
| --- | --- | --- |
| Several generations of round buttons and surfaces | Shared palette, precision corners and consistent press/focus states | One recognizable product across routes. |
| Studio dark text/control/model layers have similar weight | Pearl information zone, isolated model stage, quieter secondary tools | The part and next action become easier to identify. |
| Navigation marker animates width | Fixed-width marker scaled on the compositor | Selection feedback avoids repeated layout animation. |
| Old tests read former implementation files | Assertions follow active navigation and hotspot integration | Preserve meaningful behavior checks after module extraction. |

## Validation contract

Record pure logic/source tests, production build, real browser UI, real GLB rendering and FPS separately.
The local browser baseline uses existing `--mode flow`, visibly labelled rehearsal with no database.
Use its published `demo@dth.test` fixture; no real credentials or records. This does not certify Atlas,
API persistence, authenticated Admin, or physical fitment. Review desktop, laptop and mobile widths,
keyboard, touch, loading/error states and reduced motion. Save before/after screenshots under ignored
`test-results/premium24`. Source backups are ignored under `backups/premium24-before`.
Run `node tools/verify-premium24.mjs` from the application root to repeat the selected pure/source
regressions, import check and production build. It does not run database integration tests.
